## Tone and style notes for this project

No unusual conventions for this project — write in plain, direct executive
language. Short sentences over long ones. Lead with the headline (overall
status, biggest risk) rather than burying it under preamble.

## Curation priorities (Part B — curate_report)

No project-specific overflow priorities beyond the hard rules already
enforced in code (Blocked/At Risk/Needs Human Review Features are never
trimmed; only On Track Features and any Initiative may be condensed or
cut for space). When trimming On Track Features, prefer keeping the ones
with the most recent activity over ones that haven't changed in weeks.

## Continuity notes (Part C — write_executive_summary)

When referencing `prior_week`, name the specific Feature or Initiative
that changed rather than speaking in aggregates ("Feature X moved from At
Risk to Blocked" beats "one item got worse"). If `prior_week` is null
(first run for this project), don't apologize for the lack of history or
call attention to it being a first report — just write the summary as if
history will start accumulating from here.
